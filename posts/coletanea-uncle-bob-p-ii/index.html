Código Limpo

Capa do Livro Código Limpo

No livro O Codificador Limpo, Martin traz pontos que toda pessoa que trabalha em desenvolvimento de software deve-se atentar, principalmente na camada de soft skills, nesse sentido o livro de hoje volta para a camada mais técnica, no momento do desenvolvimento de software.

Logo no inicio Martin demonstra que todo desenvolvedor já parou algum momento para pensar se realmente realiza o desenvolvimento de um código limpo, entre essas perguntas que nos deparamos são:

  • Será que comento esse bloco de código?
  • Minha função está objetiva?
  • Será que esse nome de variável ficou bom?
  • TDD atrapalha na expansão de um projeto?

No decorrer do livro Bob vai demonstrando como podemos responder essas perguntas, e além disso traz muitos exemplos, separados em cada capítulo com o foco em uma etapa do desenvolvimento (variáveis, funções, classes, métodos, tratamento de erros e etc), deixando claro que a proposta de todo o decorrer do livro é escrever um bom código. Por um momento você pode se perguntar, mas porque criar bons códigos?

Porque o custo total para manter um código ruim é enorme.

Quem trabalha ou trabalhou como programador por algum tempo, já deve ter passado pela experiência de ter uma produtividade ruim por causa de código ruim. Algo que deveria ter levado horas para ser feito, acabou levando semanas. Uma mudança que bastava ser em poucas linhas de código, acabou precisando ser feita também em muitos outros lugares do sistema e estes precisaram ser bem entendidos para alterá-los.

Quando o projeto está no início, sempre se começa com uma alta produtividade, porém com o tempo, muitos projetos acabam reduzindo drasticamente a produtividade, e um dos pontos que Bob toca é criarmos desculpas! A gente sempre tem alguma desculpa pra dar: o prazo de entrega era muito curto; os requisitos mudaram no meio do projeto; o gerente de produtos pediu coisas absurdas, entre outras. Mas a culpa na verdade é nossa. Nós como profissionais no desenvolvimento de software devemos ser profissionais a ponto de defender a importância de escrever um código limpo, mesmo que demore mais pra ser feito.

E dentre essas defesas, um dos pontos mais simples para fazer um código limpo é sobre a regra do escoteiro. Os escoteiros possuem uma regra: deixe o acampamento mais limpo do que você o encontrou, aqui em nossa área podemos dizer, “deixe o código mais limpo do que estava antes de você mexer nele.”

É uma regra simples, mas bastante efetiva. Quando você estiver trabalhando em algum código, se encontrou algo que pode ser melhorado, melhore! Não deixe pra depois, porque o depois na verdade quer dizer nunca.

Você não precisa refatorar a classe inteira, são ações pequenas como mudar o nome de um método que não estava muito claro ou quebrar um método que estava muito grande em outros menores, você realizando essa regra estará auxiliando a criar um código mais limpo e fácil para manutenção, pois tenha certeza se você não arrumar, você voltara nesse código em um outro momento e se arrependerá de não ter feito melhorias 😆.

Para o profissional QA, o livro é excelente para entender um pouco mais de como é feito o desenvolvimento de software, entender sobre processos e nomes que muitas vezes escutamos em uma planning, daily ou refinamento, além disso trago alguns pontos que irá te auxiliar na sua carreira:

  1. Manutenção e Atualização de Testes: Quando o código é limpo e bem organizado, é mais fácil para os membros do QA manter e atualizar os testes de forma eficiente. Eles podem identificar áreas para melhorar os testes de maneira mais precisa.
  2. Aplicar código limpo nos testes automatizados: com o entendimento do livro o QA pode aplicar esse conhecimento para desenvolvimento dos seus testes, sendo eles unitário, integrado ou end-to-end, todo código que você desenvolverá poderá seguir critérios que foram apresentados no livro.
  3. Colaboração com Desenvolvedores: Ao adotar os princípios de código limpo descritos no livro, o QA pode colaborar melhor com os desenvolvedores. Ambas as equipes podem falar a mesma linguagem e compartilhar uma compreensão mais profunda do código e das funcionalidades.
  4. Leitura e Compreensão do Código: O QA precisa entender o código para criar testes eficazes. “Clean Code” promove a clareza e a legibilidade do código, facilitando para os membros do QA entenderem a lógica do software.
  5. Identificação de Pontos de Teste: A clareza do código promovida pelo “Clean Code” ajuda os membros do QA a identificar áreas críticas para os testes. Código limpo é mais fácil de analisar para determinar onde são necessários testes mais aprofundados.

Todo profissional da área deve ler esse livro, desde o PO/PM para entendimento de como é desenvolvido um código, ao engenheiro que estará desenvolvendo da melhor forma possível e ao QA para entender como esse código foi desenvolvido e como pode ser aprimorado com os testes.
